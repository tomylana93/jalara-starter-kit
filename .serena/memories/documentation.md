# Internal Documentation

- Documentation is authenticated+verified app-shell content; readers only see `published`, while management routes/actions require `Role::SuperAdmin`.
- Persistence: `documentation_categories` and `documentations`; UUIDs, one-level categories, manual integer positions, Tiptap JSON in `content`, extracted plain text in `searchable_text`, and permanent deletion. No revision history or autosave.
- `published_at` records first publication and permanently freezes the slug; switching back to draft does not clear it.
- Tiptap content is server-validated by `App\Support\DocumentationContent`; supported structure includes headings 1–3, emphasis, lists, quote/code, links, and tables. Links allow internal `/` paths or HTTP(S) only.
- Editor images are queued, non-exclusive `ImageUploadTarget::DocumentationImage` uploads (`mem:backend/media_uploads`) published to the public disk under `DocumentationContent::IMAGE_DIRECTORY` only. The endpoint is document-independent because a new document has no id while it is being written; `PublishDocumentationImageUpload` re-checks `create` on `Documentation` and applies nothing, so the author's next save is what turns a result into a referenced file.
- `DocumentationContent::imageRelativePath()` is the single definition of "this image is ours": a persisted `image` node's `src` must start with the managed prefix URL and carry no `..`, query, or fragment, and `alt` is mandatory and length-bounded. Content validation and `PruneOrphanImages` both read it, so they can never disagree about which files a document protects.
- The Tiptap `image` node is a local `resources/js/extensions/documentationImage.ts`, not `@tiptap/extension-image`: attributes stop at `src`/`alt` and it deliberately defines no `parseHTML`, so a pasted `<img>` produces no node and cannot smuggle a remote or `data:` URL into a document.
- `RichTextEditor` renders image controls only when a consumer passes `imageUploadRoute`; the node type is always registered so existing images still render in editors and the reader without upload capability.
- Search is portable lexical database search for SQLite/MySQL/PostgreSQL, limited to published documents and eight results; no vector/AI dependency.
- UI routes/components live under `resources/js/pages/documentation` and `resources/js/components/documentation`. Documentation is an internal `NavFooter` item; Repository remains external.
- Documentation controllers hold no private helpers: prop shaping belongs to `App\Http\Presenters\DocumentationPresenter`, and every document/category mutation belongs to an endpoint-specific `App\Actions\Documentation\*` action. `SaveDocumentation` stays the shared persistence collaborator behind create/update so publication, content extraction, and position rules are never duplicated.
- `ResolveUniqueDocumentationSlug` owns documentation slug normalization and collision allocation: normalize with `Str::slug`, fall back to `documentation`, exclude the current draft, and choose the first available sequential suffix beginning at `-2`. `SaveDocumentation` invokes it only while the document has never been published; a non-null `published_at` permanently freezes the existing slug.
- Management routes carry `role:super-admin` *and* an explicit `Gate::authorize` in the controller; the role middleware alone is not the authorization contract.
- A successful document create or update redirects to the management index with a success toast. Category create/update/delete and document delete also toast; both reorder endpoints stay silent.
- The management document list is fixed 10-row server-side pagination via `DocumentationTable` (`mem:backend/tables`) rendered with a custom shadcn-vue `Pagination`, deliberately not the generic `DataTable` (`mem:frontend/data_table`): no search, sort, or page-size control, and `page` is the only exposed query. `DocumentationTable::query()` applies the category-position ordering itself so `AbstractTable` appends document position and id after it; the controller therefore has to pass `direction: 'asc'`, since `TableQuery` defaults to `desc`.
- `resources/js/pages/documentation/manage/Edit.vue` is intentionally one hybrid create/edit page on `useForm`/`router.visit`. Do not split it or migrate it to Inertia `<Form>` or Precognition without re-evaluating the rich-text dirty-state guard and the management dialogs.
- `RichTextEditor` exposes every toolbar action a second time through a shadcn-vue context menu on the editor surface, with the Tiptap shortcut rendered as `Kbd`; `isMacOS()` from `@tiptap/core` picks the ⌘/Ctrl symbols so hints can never diverge from the keymap. A command opened from the menu that shows a dialog must defer opening it, because the menu restores focus to its trigger as it closes.
- The editor consumes any keystroke ProseMirror already handled (`stopPropagation` when `defaultPrevented`). Handled shortcuts otherwise bubble to window-level application listeners: `SidebarProvider` toggles on a bare Ctrl/Cmd+B with no editable-target guard, so bold also collapsed the sidebar. `GlobalSearch` guards Ctrl/Cmd+K with its own editable check and is unaffected.
- `DocumentationFactory` stores `slug` as a `Stringable`; a test reusing `$documentation->slug` as request input must cast it, or `string` validation fails.
- Global command palette is mounted in `AppShell`; Ctrl/Cmd+K opens it outside editable controls, while editor/input shortcuts remain untouched. Documentation requests start at two characters with a 250 ms debounce.
- The palette's `CommandGroup` recomputes its filter only when the search string changes, so it permanently hides any group whose items mount later. Server-filtered results must therefore render outside a `CommandGroup`, with `provideCommandGroupContext` called at the palette root because `CommandItem` still injects it, and `CommandEmpty` gated on the remote results instead of the filter count. Nesting a `ScrollArea` inside `CommandList` also collapses the list.
- In `DocumentationManagementController::index`, the `categories` and `documentations` props must remain lazily evaluated closures. The frontend pagination requests only `documentations`; without lazy closures, Inertia omits the category payload from the response but the server still executes the category query.
