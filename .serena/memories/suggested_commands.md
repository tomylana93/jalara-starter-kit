# Suggested Commands

Local and CI script entry points only. Gate topology and release automation internals: `mem:release_process`. Cost-model rationale: `docs/adr/003-ci-cost-model.md`.

- Local setup: `composer run setup`; CI env without early build: `composer run ci:setup`, or `composer run ci:setup:php` when Node is unused; development: `composer run dev`; frontend dev: `pnpm run dev`.
- Vitest: `pnpm test:unit`; watch: `pnpm test:unit:watch`.
- Pest focused: `php artisan test --compact <file>` or `--filter=<name>`; full backend: `composer test`.
- Pest browser: `composer run ci:browser`; focused: `vendor/bin/pest tests/Browser/<file> --filter='<name>'`. Needs a current `pnpm run build`.
- Database compatibility locally: `composer run test:pgsql` and `composer run test:mysql` (ephemeral podman containers, torn down after the run).
- Combined auto-fix before the gate: `composer run fix` (Rector, Pint on dirty files, ESLint, Prettier). Frontend-only: `pnpm run lint`, `pnpm run format`; checks: `pnpm run lint:check`, `pnpm run format:check`, `pnpm run types:check`, `pnpm run test:unit`. PHP-only auto-fix: `composer run rector`, `composer run format:agent`; repository-wide formatting: `composer run lint`. Checks: `composer run rector:check`, `composer run lint:check`, `composer run types:check`.
- Laravel Doctor: `composer run doctor:check` (read-only) and `composer run doctor:fix` (mutating; manual only). Outside `ci:check` and the workflow: CI runs on `:memory:` SQLite with no migrated schema, so migrations/cache/queue/session diagnostics fail there.
- Local gate scripts (same commands CI invokes): `ci:static`, `ci:vitest`, `ci:pest`, `coverage:check` / `ci:pest:coverage`, `ci:browser`. Fast tier: `composer run ci:check` = static + vitest + pest. Promotion tier (required when CI/release/Playwright config changed): `composer run ci:full` = static + vitest + coverage + browser. Rector is local-only via `composer run fix`. Pest TIA is active locally and skipped on CI through `pest()->tia()->locally()`.
- Canonical install: `laravel new <name> --using=<repo URL> --database=sqlite --pnpm --no-boost --no-interaction`. Only `--pnpm` and `--no-interaction` are load-bearing. With Laravel Installer 5.31 `--boost` is `VALUE_NONE` and is only enabled inside `interact()`, so `--no-interaction` already skips Boost; `--no-boost` stays as an explicit safeguard against reinitializing Jalara's preconfigured Boost and agent context (`boost.json`, `.ai/`). `--no-interaction` suppresses the installer's Pest scaffolding (`installPest` would otherwise remove phpunit, unpinned-update, `pest --init`, `pest --drift`). `--pnpm` keeps the lockfile and rewrites `dev`/`dev:ssr`/`setup` via `str_replace(['npm','npx','ppnpm'], ['pnpm','pnpm dlx','pnpm'])` — those scripts must round-trip unchanged.
- Installer ordering: `npx tiged <url> && composer install` (so `post-create-project-cmd` never fires), then `composer run post-root-package-install`, `key:generate`, the `extra.laravel.installer.post-create-project` hooks, then database configuration and migration, then the Node install/build. Hooks boot before `.env`/SQLite/schema exist; they must stay DB-free, noninteractive, and idempotent.
- The release-scope `installer` CI job reproduces that command from `git archive HEAD` with no `APP_ENV` set. Ordinary gate jobs export `APP_ENV=testing` and cannot detect pre-environment failures.
