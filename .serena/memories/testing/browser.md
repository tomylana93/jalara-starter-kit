# Pest Browser Tests

- Browser tests live in `tests/Browser` and run through the Pest browser plugin (`pestphp/pest-plugin-browser`), which drives Playwright as a runtime. `@playwright/test` is not installed; the bare `playwright` package plus `pnpm exec playwright install chromium` provides the browser.
- Run them with `composer run ci:browser`. They are part of `composer run ci:full`, not `ci:check`.
- `resources/views/app.blade.php` passes the page component to `@vite`, so browser tests need a current `pnpm run build`.
- `tests/Browser` binds `Tests\BrowserTestCase`, never `Tests\TestCase`. The latter calls `withoutVite()`, which stubs the `@vite` directive so the browser receives no bundle and every page renders blank — while still passing `assertNoSmoke()`. This shipped once and was caught only by screenshotting a failure.
- The suite is one file, `SmokeTest.php`: a single `visit([...])` across every main page, asserting `assertNoSmoke()` **and** a positive `assertSee()` per page. The positive assertion is load-bearing — `assertNoSmoke()` only proves the absence of console logs and JavaScript errors, so a page rendering nothing passes it. Never let the sweep degrade to `assertNoSmoke()` alone.
- Several settings screens sit behind `RequirePassword`; the sweep opens the window with `session(['auth.password_confirmed_at' => time()])`. The barrier itself stays a Feature-test concern.
- Multi-step flow coverage does not exist at this layer, and that is a known open question rather than an oversight: **the plugin's interaction fidelity against a headless component library (reka-ui) is unproven for this application.** The plugin exposes no request interception (`page.route()` was `@playwright/test`-only), so an upload's in-flight state cannot be observed; and `fill()`/`click()` against reka-ui wrappers leave Vue's reactive state empty while the DOM looks correct, so a chat send reaches the server with every request field absent. Both flows passed under the previous runner, so the application works — the harness is what is unproven. Settle this before widening the browser suite. See `docs/adr/002-test-stack-consolidation.md`.
- Authentication is `actingAs()` inside the test, not a captured storage state. There is no setup project, no auth fixture, and no shared session file.
- `RefreshDatabase` applies to `tests/Browser` through `tests/Pest.php`, the same as `tests/Feature`; browser tests use the ordinary testing database rather than a dedicated SQLite file.
- The old Playwright runner and its asset-isolation machinery (`E2E_ASSET_ISOLATION`, `build-e2e`, `hot-e2e`, per-run storage roots, `app.vite.isolated_*`, `AppServiceProvider::configureVite`) are gone. Browser tests read the ordinary `public/build`. Do not reintroduce a parallel bundle path.
- Rationale for the consolidation: `docs/adr/002-test-stack-consolidation.md`.
