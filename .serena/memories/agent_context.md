# Agent Context Infrastructure

- Custom Boost source-of-truth: `.ai/guidelines/` for always-loaded rules; `.ai/skills/` for on-demand procedures. `.ai/guidelines/release-workflow.md` owns commit, pull-request, and release policy, and `.vscode/settings.json` points the editor's commit-message and pull-request generators at it.
- Boost publication writes `AGENTS.md`, `CLAUDE.md`, and the skills selected by `boost.json` into `.agents/skills/` and `.claude/skills/`. Third-party project skills are installer-owned instead: canonical files live in `.agents/skills/`, Claude Code receives `.claude/skills/` symlinks, and `skills-lock.json` owns provenance/update metadata. `composer run agents:update` must preserve those installer-owned paths.
- Third store, tool-owned: `.ai/rules/` holds committed path-scoped rules, written only via Boost's `record-rule` MCP tool (hardcoded to `base_path('.ai/rules')`), which owns placement, frontmatter, and `index.md`. Not hand-authored, not regenerated by `agents:update`.
- Store selection: `.ai/rules` for constraints found by matching a file's path against `index.md`; Serena memory for orientation knowledge found by traversing `mem:` references. Never mirror a rule into both. Boost's generated "always use `record-rule`, never native memory" line targets session-scoped assistant memory and does not apply to Serena memory, which is committed under `.serena/memories/`.
- `composer run agents:update` is the publication entry point. It sets `BOOST_RULES_SCOPED_GUIDELINES=true` and runs `boost:update`. Run it twice after agent-context changes and confirm the second run leaves no further tracked diff.
- Because scoped guidelines are on, path-scoped package guidance is extracted into the Boost-managed `.ai/rules/boost/` subtree and indexed in `.ai/rules/index.md` instead of being inlined in the generated agent files. That subtree is regenerated every publication; rules written with `record-rule` live outside it and survive.
- `boost.json` selects supported agents and Boost-provided resources. Non-Boost MCP client configuration remains client-specific and must not be assumed identical across agents.
- Serena project bootstrap/configuration: `.serena/project.yml`; durable project memory graph: `.serena/memories/`.
- Serena 1.7 renamed the `languages` project key to `language_servers`. Configure only `vue` and `php_phpantom`: the Vue server starts its own companion TypeScript server and serves `.ts` as well, so a separate `typescript` entry only duplicates indexing.
- Serena hook cleanup runs from `SessionEnd` for both clients: Codex ≥0.145 replaced the old `Stop` event, and `.claude/settings.json` already used `SessionEnd`.
- Serena runs as one shared streamable-HTTP server on port 9121 for the configured AI coding clients. Its `--context ide` is deliberate: client-specific contexts may exclude project tools or force single-project behavior, while the shared endpoint needs the full IDE toolset.
- Because the shared context carries no client-specific tool-routing prompt, Claude Code enforces routing through `.claude/hooks/` `PreToolUse` gates instead: `require-serena-manual.py` blocks work tools until `initial_instructions` runs, and `prefer-serena-tools.py` denies built-in discovery reads of PHP and built-in edits of PHP/TS/Vue. Both fail open so a session cannot deadlock.
- `.claude/settings.json` sets `ENABLE_TOOL_SEARCH=false` so Serena's tools are never deferred.
- Composer scripts are repository-owned entry points for dependency-backed development and agent-publication tools. Prefer them over direct `vendor/bin/*`, Artisan, or package-manager calls whenever a matching script exists; Serena memory operations remain Serena-native.
- Skill availability is dynamic. Discover current skill metadata at runtime; never persist an installed-skill enumeration in guidelines or memories.
- Agent-context validation: validate custom and installer-owned skill structure, run `composer run agents:update` twice for idempotence, run Serena reference checks after memory changes, then run `git diff --check` and the required CI gate.
