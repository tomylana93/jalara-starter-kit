# Agent Context Infrastructure

- Custom Boost source-of-truth: `.ai/guidelines/` for always-loaded rules; `.ai/skills/` for on-demand procedures. `.ai/guidelines/release-workflow.md` owns commit, pull-request, and release conventions, and `.vscode/settings.json` points the editor's commit-message and pull-request generators at it.
- Generated, tracked outputs: `AGENTS.md`, `CLAUDE.md`, `.agents/skills/`, and `.claude/skills/`. Regenerate with `composer run agents:update`; do not maintain custom changes only in generated files. Exception: `.agents/skills/grill-me/` is a hand-maintained Codex-only skill that Boost neither composes nor overwrites, because it is absent from both `.ai/skills/` and the `boost.json` skill list.
- Third store, tool-owned: `.ai/rules/` holds committed path-scoped rules, written only via Boost's `record-rule` MCP tool (hardcoded to `base_path('.ai/rules')`), which owns placement, frontmatter, and `index.md`. Not hand-authored, not regenerated by `agents:update`.
- Store selection: `.ai/rules` for constraints found by matching a file's path against `index.md`; Serena memory for orientation knowledge found by traversing `mem:` references. Never mirror a rule into both. Boost's generated "always use `record-rule`, never native memory" line targets session-scoped assistant memory and does not apply to Serena memory, which is committed under `.serena/memories/`.
- This repository supports exactly two agents: Claude Code and Codex. `boost.json` lists exactly `claude_code` and `codex`, and no other agent may gain client configuration, plugins, hooks, or ignore entries here.
- `composer run agents:update` is the only publication entry point. It sets `BOOST_RULES_SCOPED_GUIDELINES=true`, runs `boost:update`, then runs the `.ai/scripts/agent-context.php` sanitizer, which strips unsupported-agent references that upstream Boost skills ship (currently a shadcn-vue MCP editor-table row) and hard-fails if any survive. Fix such a reference in the sanitizer, never in the generated file. `composer run agents:check` is the read-only counterpart and must pass, followed by a second `agents:update` that leaves no tracked diff. `config/boost.php` is unpublished, so the env var is the only lever.
- Because scoped guidelines are on, path-scoped package guidance is extracted into the Boost-managed `.ai/rules/boost/` subtree and indexed in `.ai/rules/index.md` instead of being inlined in the generated agent files. That subtree is regenerated every publication; rules written with `record-rule` live outside it and survive.
- `boost.json` selects supported agents and Boost-provided resources. Non-Boost MCP client configuration remains client-specific and must not be assumed identical across agents.
- Serena project bootstrap/configuration: `.serena/project.yml`; durable project memory graph: `.serena/memories/`.
- Serena 1.7 renamed the `languages` project key to `language_servers`. Configure only `vue` and `php_phpantom`: the Vue server starts its own companion TypeScript server (spawned from `VueLanguageServer/vue-lsp/node_modules/.bin/typescript-language-server`) and serves `.ts` as well, so a separate `typescript` entry only duplicates indexing. `serena project health-check .` proves this — it creates two language-server instances while a third TypeScript process starts under the Vue manager.
- Serena hook cleanup runs from `SessionEnd` for both clients: Codex ≥0.145 replaced the old `Stop` event, and `.claude/settings.json` already used `SessionEnd`.
- Serena runs as one shared streamable-HTTP server on port 9121 for Claude Code and Codex. Its `--context ide` is deliberate and must not become `claude-code`: that context excludes `search_for_pattern`, `list_dir`, `find_file`, and `execute_shell_command`, and its `single_project` flag disables `activate_project`, which the session-start hook drives.
- Because the shared context carries no client-specific tool-routing prompt, Claude Code enforces routing through `.claude/hooks/` `PreToolUse` gates instead: `require-serena-manual.py` blocks work tools until `initial_instructions` runs, and `prefer-serena-tools.py` denies built-in discovery reads of PHP and built-in edits of PHP/TS/Vue. Both fail open so a session cannot deadlock. Serena's `print-cc-system-prompt-override` is intentionally unused because `--system-prompt` replaces the harness prompt rather than extending it.
- `.claude/settings.json` sets `ENABLE_TOOL_SEARCH=false` so Serena's tools are never deferred; this is what makes Serena's documented long-session tool drift inapplicable here.
- Composer scripts are the repository-owned entry points for dependency-backed development and agent-publication tools. Prefer them over direct `vendor/bin/*`, Artisan, or package-manager calls whenever a matching script exists; Serena memory operations remain Serena-native.
- Skill availability is dynamic. Discover current skill metadata at runtime; never persist an installed-skill enumeration in guidelines or memories.
- Agent-context validation: validate custom skill structure, run `composer run agents:update`, `composer run agents:check`, then `agents:update` a second time for idempotence, run Serena reference checks after memory changes, then run `git diff --check`.
